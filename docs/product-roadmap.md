# 刻词 Engrave · 产品需求清单（2026-10-12 定稿）

> 结合手表场景与目标用户实际情况整理的需求判定与优先级清单。
> 本文件用于跟踪哪些需求要做、做到什么程度、哪些明确不做。

---

## 一、目标用户与场景前提

- **目标用户**：学校里无法使用手机的学生，手表是**唯一设备**
- **网络环境**：校内**没有网络**（无 WiFi、无蜂窝）
- **使用时段**：课间十分钟、午休、晚自习（做英语卷子/阅读）、宿舍睡前、吃饭排队——每次几十秒到几分钟
- **使用约束**：
  - 使用时段内**可以正常看屏**（上课不背单词，不存在课上偷用场景）
  - 多数时段**不能出声**（自习室、宿舍夜间、排队时公放不礼貌）
  - 没有手机可以代劳任何操作
  - 手表一旦重置或更换，数据即丢
  - 整句翻译的真实触发场景：**晚自习做英语阅读/完形遇到长难句**，手边只有手表

**但是**：后续可能会做联网相关功能，但是最主要要保存离线可用

### 现状盘点（2026-10-12 实测）

| 项 | 现状 |
|---|---|
| 离线能力 | 目前全应用**零 INTERNET 权限**，天生全离线 |
| 词典覆盖 | `ecdict_core.db` 59,137 词条 + 31,185 词组，课本常见词全命中 |
| 语音 | 无任何语音识别代码（SpeechRecognizer 未使用） |
| 触觉 | 学习过程**零触觉反馈**（仅提醒通知有振动） |
| Wear 原生能力 | 无 Tile、无表盘复杂功能、无 AOD 处理 |
| 备份 | 只有手动备份到文件，无自动备份 |

## 二、立即可做（改动小、完全离线可用）

> 风险最低、最贴学生场景，建议优先开工。均不动数据库。

### ① 对/错（会/不会）触觉反馈 —— 倾向划掉（不做，不用管）

- **2026-10-13 讨论结论**：卡片是自我评估（左滑会、上滑不会），不是对错判断；且评分后卡片立即滑走，动画本身就是"操作生效"的确认，再震动是重复信号，还有耗电成本
- **评分机制本身不多余**：会/不会是 SM-2 调度的唯一输入，去掉等于放弃间隔重复——要砍的是震动，不是评分
- **候选方案**（确认a）：
  - A. 整条划掉，学习过程零震动

### ② 首页任务量展示：大数字改进度条 （留档，暂时不做）

- **场景**：课间就 10 分钟；现有会话缓存机制已能续背，真正的问题是首页大号「10/1987」的视觉压迫感
- **已定方案**（2026-10-13 用户确认方向，代码尚未实施）：
  - 大号「10/1987」撤掉，换成**细横条进度条**（手表小屏上比圆环省地方）
  - 总数保留但降级为灰色小字一行：「已学 10 · 共 1987」
  - 「待复习 9 · 新词 10」那行小字不动
  - 「开始学习」按钮文案 AB 两案都保留、以后选：
    - A. 只显示「开始学习」（最干净）
    - B. 「开始学习 · 约 X 分钟」（按每张约 15 秒估算，把数量翻译成时间，匹配课间决策方式）——实现时留常量开关切换
- **改动**：UI 层（双端 HomeScreen）+ core HomeViewModel 按钮文案
- **范围**：双端
- **复杂度**：低

### ③ 优化：通知点开直达学习页（2026-10-14 缩小范围：只做直达，去掉按钮和条件发送）

- **场景**：手表本质是通知设备；现在通知点开只进 App，还要再找入口
- **内容**：点提醒通知直接进学习页（自带断点续背）；**不再**挂「开始复习 N 个」按钮、**不做**「无待复习不发」的条件判断
- **改动**：ReminderReceiver 的 contentIntent 加直达 extra；双端 MainActivity 解析 extra 直达（launchMode singleTask + onNewIntent）
- **范围**：双端
- **复杂度**：低

### ④ 会话切片：「快速复习 10 个」+「今天只复习」（仅留档，不做）

- **场景**：`sessionSize = dueNow + newRemaining` 无上限，积压 200 个时学生看到数字就不敢开始——**弃坑第一杀手**
- **内容**：首页提供「快速复习 10 个」小入口，把大任务切成"一小口"；支持「今天只复习不学新词」
- **改动**：UI 层（首页）+ ViewModel 队列逻辑
- **范围**：双端
- **复杂度**：中低

## 三、需设计（明确有价值，先定方案再动手）

### ⑤ a Tile + 表盘复杂功能（仅 :app）

- **内容**：手表左滑一屏看到「待复习 12 / 今日已完成 20」，点一下直接开背；表盘上放待复习数
- **改动**：系统层，新增模块
- **范围**：**仅 Wear 版**（依赖 Wear 共享库）
- **复杂度**：中

### ⑥ b 桌面小组件（仅 :app-phone）（仅留档，暂时不做）

- **内容**：同上的非 Wear 手表版本
- **说明**：与 ④a 是**两套不同实现**，不能互用
- **范围**：**仅 :app-phone**
- **复杂度**：中

### ⑦ 本地自动备份（目前手动备份存在，暂时不做）

- **场景**：手表重置/换表 = SM-2 学习进度全丢，且**无云可救**（没手机没网）
- **内容**：定期自动把进度落盘到手表本地文件；放假回家用电脑 adb 取回
- **改动**：系统层
- **范围**：双端
- **复杂度**：中

## 四、需技术验证（先验证可行性，再决定投入）

### ⑧ a 词典扩展：支持反义词，同义词/近义词，句型句式，最后讨论

### ⑧ b 离线整句翻译（用户已拍板要做）

- **问题**：句式、整句翻译——词典解决不了，必须上机器翻译引擎
- **候选**：Marian int8 ONNX（Xenova/opus-mt-en-zh，112.7MB）
- **验证顺序（按风险从高到低）**：
  1. **推理耗时**（生死线）：手表 CPU 跑 7700 万参数模型，单句超过 3~5 秒体验即崩
  2. **内存**：Watch4 只有 1.5GB RAM，ONNX Runtime + 模型常驻可能 OOM
  3. **分发方式**：无 INTERNET 权限 + 校内无网 ⇒ 模型**不能联网下载**；只能随 APK 分发（包体 9MB → 120MB+）或用户在家预先手动导入（可复用现有文件选择器）
  4. **模型裁剪**：只保留 en→zh 单向、裁剪词表缩体积
  5. **备选**：找更小的 distilled/tiny 模型
- **建议路径**：先做 ⑦a 解决"偏词偏短语"，再决定是否为"整句翻译"扛 112MB 模型

### ⑨ 离线语音识别（留档，暂时不做）

- **场景**：课间、宿舍可以出声；课堂/自习不行
- **硬门槛**：无网环境下 Android 语音识别**通常直接失效**；`EXTRA_PREFER_OFFLINE` 只是"偏好"离线，无本地语言包时要么失败要么偷偷走网。Wear 设备（尤其无 GMS 的国产表）基本没有离线识别包
- **验证方式**：写一个几十行的最小测试程序直接在表上测，通过再谈，不通过永久划掉
- 手表不支持官方的离线语音，需要自己跑本地识别
- **复杂度**：高（可能直接判死）

## 五、已明确划掉（不做）

| 功能 | 划掉理由 |
|---|---|
| CSV / Anki 导出 | 手表没有文件出口，插不了线、分享受限 |
| 词汇量测试 | 需要长时间连续作答，典型手机/PC 任务 |
| 统计页复杂图表 | 谁会在 1.2 寸圆屏上研究 30 天热力图 |
| 云同步 / 云端词书下载 | 校内无网，方案不成立 |
| 手机 Data Layer 备份 | 用户没有手机，同步给谁 |
| TTS 语速调节 | 场景存在但优先级低，需求不明确 |
