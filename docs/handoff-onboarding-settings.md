### 1.2 双端事实

### 1.3 引导现状（4 步）

`core/.../ui/onboarding/OnboardingViewModel.kt` + `app`/`app-phone` 各自的 OnboardingScreen：

- 步骤：**0 选词书（单选 chip 列表，默认选第一本）→ 1 每日数量（转轮）→ 2 提醒（双转轮 + "开启提醒"按钮，可不开直接下一步）→ 3 完成（汇总 + 开始使用）**。
- 开启提醒即触发系统通知权限请求；**被拒（含"不再询问"）直接跳系统通知设置页**，返回应用后还引导电池优化白名单。
- `setReminder()` 在引导**中途就写 DataStore + 排闹钟**（`OnboardingViewModel.kt:70-78`）；只有 `finish()` 才写词书、每日数量、`completeOnboarding()`（同文件 89-101）。即：没走完引导，提醒设置也已被改动。
- step / 选书 / 数量全部是 VM 内存态 MutableStateFlow，**引导中途进度不落库**。

**真机实测（2026-10-11，Watch4，release 包）**：引导第 3 步开启提醒 → 跳系统通知设置页 → 按 BACK 后落到系统启动器；重新进入应用，引导从 **1/4 重新开始**，已选书重置为默认。进程为何重建未取证据（可能与任务栈/BACK 双发有关），但"引导中途把用户甩出应用、回来进度丢失"是复现确认的现象。

## 二、任务①：设置选项重排 —— 推荐方案（供与用户讨论后定稿）

### 2.1 当前结构的问题（代码可证实）

1. **设置页是一个无分组长列表**，4 项混排：学习计划（新词/提醒）与显示偏好（释义/发音）没有区隔；提醒区 3 个高 item，进去改释义要滚动。
2. **释义用循环 Chip**：三态要连点、看不到全部选项，是最不直观的一个控件。
3. **"学什么"（词书）和"学多少"（每日新词）分属两页**，概念同属学习计划却不在一起。
4. 我的页 5 个菜单平铺，"学习统计"（看数据）和"数据管理/使用指引"（工具）与设置同级，没有层级。
5. 双转轮常驻占据设置页近一半高度，即使提醒关闭。

### 2.2 推荐分类（三级心智：学什么 → 怎么学/何时提醒 → 看起来怎样）

**A. 「我的」页菜单重排为 3 组**（沿用现有灰线分组样式，零新组件成本）：

```
学习          词书管理（副标题：已启用 N 本 / 全部）
设置          ↓ 进入重排后的设置页（见 B）
其他          学习统计 · 使用指引 · 数据管理
————          关于区保持在最底部不动
```

**B. 设置页内部按 3 个 ListHeader 分组，顺序按调整频率与认知流排队：**

```
设置
── 学习 ──
1. 词书            Chip 跳词书管理页（副标题显示当前启用：初中词汇 等 1 本 / 全部词书）
2. 每日新词        行内显示当前值；点击展开 NumberWheel（或保留转轮常驻，二选一，推荐展开）
── 提醒 ──
3. 每日提醒        开关行：右侧 Switch，副标题"每天 08:00" / "已关闭"；
                   开启时下方才展开时/分选择器（关闭时不占高度）
── 显示与声音 ──
4. 释义显示        三分段选择器：中文 / English / 中英（替代循环 Chip，一眼可见三态）
5. 单词发音        开关行（右侧 Switch，替代整行 Chip）
```

理由：① 手表上深导航返回成本高（上一轮滚动恢复 bug 的教训），所以**不新造二级菜单，全部保留在一页**，只用 header + 内联展开做分组；② Switch 行符合 Wear 习惯、比"整行 Chip 变文案"易扫读；③ 提醒/新词默认折叠/展开策略让首屏从 ~7 个高 item 降到 3 行。

**C. 手机端**：屏幕空间足，三组用 SectionHeader + 行内 Switch/分段按钮平铺即可，不需要折叠；分组与顺序与手表一致。

### 2.3 需要用户拍板的决策点

1. 词书管理入口是否加进设置页"学习"组（同时我的页也保留，两处都能进）？还是设置页不放、只靠我的页？
2. 每日新词转轮：常驻 or 点击展开？（推荐展开）
3. "学习统计"放"其他"组还是留在我的页更靠前位置（它是高频查看项）？
4. 页面标题是否从"背单词设置"改为"设置"？
5. 释义分段控件三选一在圆/方屏上的宽度需真机确认（可能要做成横排三个小 Chip）。

> 以上是**推荐，不是已定稿**。新一轮先和用户确认 2.3，再动代码。

## 三、任务②：新手引导优化 —— 已附可操作原型

### 3.1 原型（用户可直接点击走查）

**`docs/onboarding-prototype.html`**（自包含单文件，无外部依赖；浏览器打开后点 450×450 的"手表屏幕"即可）。

流程（4 步压成 3 步，完成页并入最后一步按钮）：

1. **选一本词书**：卡片列表（书名+词数+选中勾），默认选第一本；主按钮"就用这本"；副文案说明以后可换。
2. **每天学多少新词**：大数字 + −/+ 步进、5/10/20/30 快捷档、范围提示（5–50、复习自动安排）。
3. **定个学习提醒**：一张开关卡片；首次开启弹**应用内**系统权限对话框（原型内模拟）：
   - 允许 → 开关亮，展开时/分步进器（5 分钟一档），主按钮"开始背单词"；
   - 不允许 → **不跳系统设置**，原地黄色提示"可稍后在我的→设置开启，不影响使用"，流程不中断；
   - 不想要提醒 → "暂不提醒，直接开始"。
4. 结束页：✅ + 三项选择汇总 + "开始学习"（可重看）。

原型同时承载文案草案，用户确认文案后实现直接照抄。

### 3.2 实现要点与必避的坑（给新一轮）

1. **权限链路改造**：引导页开启提醒只发 `ActivityResultContracts.RequestPermission()` 对话框；**删除"被拒即跳系统通知设置页"的逻辑**（`OnboardingScreen.kt` 中 `openNotificationSettings` 分支在引导场景不要；设置页里的二次引导可保留）。电池白名单引导移出引导链路（延后到首次进主页或保留在设置页）。
2. **落库时机**：提醒选择改为和词书/数量一样，只在 `finish()` 里统一写 `setReminderMinutes` + `ReminderScheduler.schedule`；权限若已授予才排闹钟，未授予写 null（或写用户选择的时间但不排闹钟——建议与用户确认：选了时间但没权限时，设置页应显示什么）。删除引导中途 `setReminder` 即写库的行为。
3. **进度防丢**：评估是否把引导中途选择持久化（DataStore 或 onSaveInstanceState），至少保证跳系统界面/旋屏后不回到 1/3。若采纳新方案不离开应用，风险大幅降低，但权限对话框期间进程被杀仍可能丢——建议 finish 之外不落库、内存态即可，与用户确认接受度。
4. 第 2 步步进器：现网是 NumberWheel 转轮；原型是 +/− + 快捷档。实现时可保留 NumberWheel（成熟组件）外加 5/10/20/30 快捷档 Chip，或照原型做步进——**问用户**。
5. 完成页不再单独一步后，`OnboardingUiState.step` 范围 0..2，`canNext` 逻辑相应简化。
6. 双端两份 OnboardingScreen 都要改，core 的 VM 改动两端共用。
7. 保留"没书也能走完引导"（books 为空时 `setActiveBooks(emptySet())` = 全部）。
8. 释义显示/发音**不进引导**（默认 中英都要 / 发音开），靠重排后设置页触达——已在原型说明里写明，用户若想加一步需明确提出。
